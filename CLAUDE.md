## Commands

```bash
# Start full dev environment (Laravel server + queue worker + Vite, concurrently)
composer dev

# Build frontend assets
npm run build
npm run dev          # Vite HMR dev server only

# Run tests (clears config cache first)
composer test
php artisan test --filter=TestClassName   # single test class
php artisan test --filter=test_method_name  # single test method

# First-time setup (install deps, .env, key, migrate, npm build)
composer setup

# Useful artisan commands
php artisan migrate
php artisan queue:listen --tries=1 --timeout=0
php artisan config:clear
php artisan view:clear
```

## Architecture Overview

### Application Type
Full B2B2C print shop platform with e-commerce, multi-department job workflow, staff management, invoicing (Paystack), push notifications (Web Push/VAPID), and a mobile API (Sanctum).

### Two Separate Portals

**Customer Portal** (`routes/web.php`, layout `layouts/theme.blade.php`)
- Middleware `customer.portal` — allows guests and customers; redirects staff to admin
- Auth at `/login` and `/register`
- Product browsing → order creation → payment → tracking

**Staff/Admin Portal** (`routes/admin.php`, layout `layouts/admin.blade.php`)
- Auth at `/staff/login` and `/staff/register`
- Middleware `admin.permission:{permission}` enforces role-based access at the route level
- 20+ roles defined in `config/printbuka_admin.php` — each role maps to an array of permission strings; `super_admin`/`admin`/`IT` use `['*']`
- `User::hasAdminAccess()` and `User::canAdmin($permission)` are the programmatic checks

### Permission / Role System
All roles and their permission sets live in `config/printbuka_admin.php`. Key sections:
- `roles` — maps role slug → permission array
- `priorities` — role priority scores (super_admin = 100, customer = 0)
- `departments` — maps role → department label
- `workflow_phases` — 6-phase job workflow definitions with gates and responsible roles
- `priorities` (job priorities) — `🔴 Urgent`, `🟡 Normal`, `🟢 Low` (these are stored as-is in the DB; do not rename them without a migration)

### Livewire Volt Components
Files prefixed with `⚡` in `resources/views/components/` are Livewire Volt single-file components — they contain an anonymous PHP class + the Blade template in one file:
```
resources/views/components/product/⚡search.blade.php
```
Referenced as `<livewire:product.search />`. The `⚡` prefix is intentional; do not rename these files.

### Image Handling
`app/Support/MediaUrl::resolve($path)` is the single entry point for all image URLs. Resolution order:
1. Data URI → pass-through
2. Cloudinary resource ID → build CDN URL via `CloudinaryUrl`
3. Full URL → return as-is (normalise host if needed)
4. Absolute local path → check storage disk
5. Relative storage path → check if file exists, serve storage URL
6. Public path → `asset()`
7. Last resort → attempt Cloudinary upload

All product/job images go through Cloudinary. Config: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.

Product image placeholder (for missing/broken images): `public/img/product-placeholder.svg`.

### Site Settings
`app/Support/SiteSettings` loads config rows from the `site_settings` DB table (5-min cache). Access via the `$siteSettings` variable shared to all views by `AppServiceProvider`. Covers contact info, pricing defaults, service prices, maintenance mode.

### Key Config Files
- `config/printbuka_admin.php` — roles, permissions, workflow phases, dropdowns for orders
- `config/printbuka_services.php` — service catalog (Direct Image, UV-DTF, DTF, Laser Engraving) with pricing
- `config/cloudinary.php` — CDN credentials and default folder (`printbuka`)

### Order Workflow (6 Phases)
`Order::status` moves through: `Quote Requested` → `Analyzing Job Brief` → `Design / Artwork Preparation` → `In Production` → `Quality Check & Packaging` → `Delivery In Progress` → `Client Review — Satisfactory`

Advancing phases requires an operations manager approval (`requested_next_status` + `approve-forward`). See `config/printbuka_admin.php` under `workflow_phases` for gates and responsible roles.

Job order numbers follow the `PB-YYYY-XXXX` format generated by `app/Support/ReferenceCode`.

### Payments
Paystack is the payment processor. Keys: `PAYSTACK_PUBLIC_KEY`, `PAYSTACK_SECRET_KEY` in `.env`. The existing `PaymentController` handles callbacks. When integrating Paystack on new flows, follow the existing controller pattern.

### Push Notifications
Browser Web Push via `laravel-notification-channels/webpush` (VAPID). Staff/admin pages register a subscription client-side (`resources/js/webpush.js`) against `POST /admin/web-push-subscriptions`, stored via `User::webPushSubscriptions()` (a polymorphic relation to the package's `push_subscriptions` table). `App\Notifications\StaffPushNotification` delivers to the `database` channel always, plus `WebPushChannel` when the user has a subscription. Keys: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — generate with `php artisan webpush:vapid`. Delivered notifications are shown by the service worker at `public/staff-sw.js`.

### Frontend Stack
- **Tailwind CSS v4** + **DaisyUI v5** — use DaisyUI component classes (`btn`, `card`, `badge`, `modal`, etc.) for UI elements
- **Custom design system** in `resources/css/app.css` — brand-prefixed classes: `.pb-btn-primary`, `.pb-card`, `.pb-input`, `.pb-table`, `.pb-badge-*`, etc. Use these for admin UI
- **Icons** — `blade-ui-kit/blade-heroicons` (Heroicons v2). Syntax: `<x-heroicon-o-icon-name class="w-5 h-5" />` (outline) or `<x-heroicon-s-icon-name />` (solid)
- **Fonts** — Inter (body), DM Sans, DM Serif Display via Google Fonts

### Cloudflare Turnstile (CAPTCHA)
Applied via `VerifyTurnstile` middleware on public-facing forms. Keys: `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`.

### Mobile API
Sanctum token auth at `routes/api.php`. Token prefix `pb_`, 12-hour expiration (`SANCTUM_TOKEN_EXPIRATION=43200`).

### Default DB / Cache / Queue
All three default to `database` driver (SQLite locally). `app/Support/SafeCache` wraps cache operations to handle missing tables during migrations gracefully.
